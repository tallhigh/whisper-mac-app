This release is about what the app actually captured while recording, and what it did
with the text afterwards. Both problems were found by measuring the audio coming in
rather than trusting what the app reported.

### System audio is chosen by app, not by process

When you record the other side of a call or a video, you pick which app to capture.
That list used to come straight from Core Audio, which thinks in processes — and a
browser does not play sound through the process you think of as the browser. Chrome
plays through a renderer helper, so the list offered `com.google.Chrome.helper` and
never "Google Chrome", and capturing Chrome's main process produced nothing at all
without saying so.

The list now shows apps: one entry per app, under the name you know it by, covering
every process it plays through. The choice is resolved again when recording starts, so
it keeps working when the browser moves the audio to a different helper — which it does
whenever you change tabs.

Picking an app that has since stopped playing is now refused before recording, instead
of producing an empty recording.

### You can see which sources are coming in

Recording the microphone and system audio together now shows **two level meters**, one
per source, in place of a single combined one. A combined meter cannot tell you the
difference between "both sides are coming in" and "the microphone is fine and the other
side is silent" — those look exactly alike.

If system audio stops arriving for five seconds, the recording sheet now says so in
words. It is not an error and the recording carries on: the microphone side is still
being written.

### Live text now works while recording system audio

The words-as-you-speak preview only ever worked when recording the microphone on its
own. With system audio, or with both, it produced nothing at all. It works in every mode
now.

### The live transcript is kept

The preview shown while recording is now saved next to the recording as a `.txt` file
whatever output formats you have chosen. Before, with only `srt` and `vtt` selected — an
ordinary choice if you want subtitles — it was written nowhere and lost the moment the
recording ended. The **History** tab lists both transcripts of a recording and lets you
switch between them. The accurate one opens by default; the preview is labelled
`txt · live`.

### Worth knowing

Recording captures the **microphone only** unless you say otherwise. The Source setting
is at the top of the recording sheet — choose "Microphone + system audio" to get both
sides of a call.
